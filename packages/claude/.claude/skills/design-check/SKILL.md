# design-check — 画面の見やすさを点検する

**適用範囲は keiba リポジトリ（`~/ghq/github.com/a1yama/keiba`）だけ。**
dotfiles 経由でグローバルに置いてあるが、中身はこのリポジトリ固有の失敗の記録なので
別プロジェクトの画面には当てない。以下のパスは全て keiba のリポジトリルート基準。

2026-08-23〜24 の1日で、実物を見ずに推測でデザインをいじって **8回連続で外した**。
このスキルはそのとき踏んだ失敗だけを並べてある。**推測で直す前にここを通す。**

外した原因はほぼ全部同じで、**「見やすくなった気がする」で判断したこと**だった。
だから手順の中心は計測で、チェックリストはその答え合わせに使う。

⚠️ 汎用のUI監査（キーボード操作・ARIA・アニメーション）は `web-design-guidelines`（Vercel）が持つ。
守備範囲が違うので**両方かける**（末尾の表を参照）。

## 手順

### 1. 実物を測る

本番 https://keiba.a1yama.com/ をブラウザで開き、`scripts/measure.js` を
`javascript_tool` に貼って実行する。コードだけ読んで直すと外す。

**スマホ幅（390-430px）を必ず測る。** 所有者はスマホで見ている。
`resize_window` は成功を返しても `innerWidth` が変わらないことがあるので、
スクリプト冒頭に幅を渡して `<main>` 側で代用する:

```js
const __W = 394;  // measure.js の前にこの1行を足す
```

⚠️⚠️ **この代用ではブレークポイント（`sm:` `md:` `lg:`）を検証できない。**
Tailwind のブレークポイントは**ビューポート幅**で決まるので、`<main>` を 390px に
しても `sm:` は効いたままになる。実機では外れる指定が効いた状態を見ているので、
**実機では起きない不具合が見え、実機で起きる不具合が見えない**。
2026-08-24 に「棒が 24px に潰れている」と誤検出した（実機相当では 324px あった）。

ブレークポイントを含む部分を測るときは、対象から `sm:` 付きクラスを外してから測る:

```js
const saved = [];
for (const el of document.querySelectorAll('対象のセレクタ, 対象のセレクタ *')) {
  saved.push([el, el.className]);
  el.className = el.className.split(/\s+/).filter(c => !c.startsWith('sm:')).join(' ');
}
// …ここで測る…
for (const [el, cls] of saved) el.className = cls;   // 必ず戻す
```

返る JSON で見るのは `page_overflow_px`（0でなければB違反）、`overflowing`（犯人）、
`body_font` / `body_line_height.ratio`（D。1.7が基準）、
`tables[].col_widths` と `row_heights`（A）、
`header_cells` と `colspans` が一致しているか（A）、`undefined_vars`（C）。

**出走表は馬を1頭展開してからもう一度測る。** 展開行の `colSpan` と、そこで再発しやすい
横スクロールは展開しないと現れない。既存のテストが全部 `expandedHorse={null}` だったため
誰も踏んでいなかった、という事故がそのまま同じ形で起きる。

```js
document.querySelector('tbody tr').click();
```

### 2. チェックリストを当てる

下のA〜Fを上から当てる。**該当しない節も「見て該当しなかった」と言えるまで読む** —
過去の失敗は全部「その節を見ていなかった」から起きている。

### 3. 直して、同じものを測り直す

前後の数値を並べる。「はみ出し 304px → 0」のように書けない直しは、直っていない可能性が高い。

### 4. テストを通す

```bash
cd frontend && npm test -- --run && npx tsc --noEmit
```

`npx tsc --noEmit` を省かない。vitest は型を見ないので、取り下げた表示の復活ガードは
型検査でしか効かないものがある。

## 報告の形

点検結果は指摘ごとにこの3点を揃えて出す。揃わないものは指摘ではなく感想なので出さない。

```
<どこ（ファイル:行 または 画面の場所）> — <何が起きているか>
  計測: <前の数値> → <直した後の数値>
  根拠: <チェックリストのどの項目か / なぜそれが読みにくさになるか>
```

該当なしのときは「A〜F 全て該当なし（計測値: はみ出し0px / 行間1.7 / 未定義変数0）」のように、
**測った値を添えて**該当なしと言う。値の無い「問題ありません」は書かない。

## チェックリスト

### A. 表の幅と折り返し（いちばん多く踏んだ）

- [ ] **テキスト列に `w-full` で余りを吸わせ、数字の列は `w-px` + `whitespace-nowrap`。**
      幅を与えないとブラウザが余白を全列に均等配分し、数字が1100px幅に散って間延びする。
- [ ] **余りを1列に吸わせたら、他の列は全部 `whitespace-nowrap`。**
      `<th>` と `<td>` の**両方**に要る。片方だけだともう片方が折り返す。
      → 3連続で踏んだ: 馬名が2行 / 「時計先行」バッジが3行で行高25→74px / ヘッダが縦書き。
      `row_heights` が1行だけ突出していたらこれ。
- [ ] **馬名は切り詰めない。** `max-w-*` と `.truncate` を馬名セルに付けない。
      スマホで「グ…」と1文字になった。**横スクロールは許容する**（所有者の明示指示。
      収めることより読めることが優先）。
- [ ] **幅の配り方は `table-fixed` + 割合。** これは3回失敗して分かった（2026-08-24）:
      | やり方 | 結果 |
      |---|---|
      | 列に幅を与えない | 数字が枠いっぱいに均等散布されて間延びする |
      | テキスト列に `w-full` | テキスト列が 62〜91% を吸い、**行の中に数百pxの空白の帯** |
      | 表に `max-w-*` | 今度は**枠の右に隙間が残る**（所有者が嫌う） |
      | **`table-fixed` + テキスト列に割合** | 枠が埋まり、行内の空白も出ない ✅
      直したら `measure.js` で「表の幅 / 枠の内寸」を測る。**100% でなければ隙間が残っている。**
- [ ] ⚠️⚠️ **`table-fixed w-full` には `min-w-[Npx]` を必ず併記する。**
      表幅が親幅に固定され、親の `overflow-x-auto` が**決してスクロールしなくなる**。
      列数ぶん割った幅が端末幅に反比例して縮み、`whitespace-nowrap` のヘッダが
      隣の列と重なる（10列の表が 390px 端末で1列 26px になっていた）。
      **広い画面は枠を埋め、狭い画面は横スクロール**、が両立の形。
      狭い画面で「表の幅 > 親の内寸」になっているかを測って確かめる。
- [ ] **項目が3つ程度の表は、表をやめる。** 3列を枠いっぱいに広げると右半分が丸ごと空く。
      **横棒**にすると幅が「値の大きさ」という意味を持つので空白が生まれず、
      値の差も一目で分かる（妙味の期待値をこれに変えた）。
- [ ] **コメントを根拠にしない。** 「馬名列を上限つき固定幅にする」と書いてある表の
      実装が `w-full`（全部吸う）で真逆だった実績がある。必ず実測で確かめる。
- [ ] **展開行の `colSpan` は `<thead>` の実セル数と一致しているか。**
      展開行の中身は幅を明示指定しているので、ズレると余った列がスクロール枠の外へ
      押し出され、**展開しただけで横スクロールが再発する**。列を足したら必ず更新する。
      `measure.js` の `colspans` と `header_cells` を突き合わせる。

### B. 横スクロール

- [ ] **ページ全体が横スクロールしていないか**（`page_overflow_px === 0`）。
      表の中だけスクロールするのは可。
- [ ] **JSX の `map` で並べた要素の間には空白テキストノードが無い。**
      各要素が `whitespace-nowrap` だと**改行できる場所が1つも無くなる**。
      横並びにする行は `flex flex-wrap` にする。→ 889px vs 394px viewport を作った。
- [ ] 展開行の幅は `100vw` ではなく `calc(100cqi - 1rem)`。
      ページはカード幅に収まっているので viewport 基準だと箱がカードより広くなる。
      `-1rem` は `<td>` の `px-2` ぶん（これが無いと16px残る）。

### C. 配色

- [ ] **参照している CSS 変数が `globals.css` に定義されているか**（`undefined_vars` が空）。
      未定義でもエラーにならず透明や inline fallback で黙って誤魔化されるため、
      目視では気づけない。`design-tokens.test.ts` がCI側で検算する。
      **`var(--x, #hex)` の fallback を書かない** — 取り残しが見えなくなる。
- [ ] **本文のコントラストは 4.5:1 以上**（同テストが全トークンを計算する）。
      `#71717a` は 4.12:1 で落ちる。
- [ ] 罫線は実線ではなく明度差 `rgba(255,255,255,.07)`。
      行数ぶん縞になって視線が横に切られるため。位置は**行ホバー**で示す。
- [ ] **面の分離は「コントラスト比」ではなく `ΔL*` で測る（8 以上）。**
      WCAG の比は分母に +0.05 を足すので、**暗い面どうしでは原理的に 1.0 付近に張り付く**。
      地 #09090b とパネル #15171d は比 1.11 で「差が無い」に見えるが、実際の
      ΔL* は 5.3 で下限に張り付いていた（画面が「のっぺり」して見える正体）。
      ΔL* を上げたうえで**枠線も1本**入れる（明度差だけだと暗所で潰れる）。
- [ ] **面の定義は `.panel` の1箇所か。** 同じ見た目を各所に手書きコピーすると、
      トークンを変えても一部だけ取り残される（実際5箇所に散っていた）。
- [ ] **自前のクラスは `@layer components` に入っているか。** Tailwind v4 の
      utilities は `@layer utilities` に入るが、**レイヤーに属さないルールは
      全レイヤーより優先される**ので、素で書くと `className="panel mt-0"` の
      `mt-0` が黙って効かない。lint も型検査も通り、コメントに「打ち消す」と
      書いてあるのに打ち消せていない、という形で残る。
- [ ] **塗る面積が増えたら色数を減らす。** 小さいバッジで成立していた
      赤/橙/黄の3色は、**セル全体を塗ると騒がしい**。面で見せるときは
      色相を1つに固定して**濃淡だけ**で段階を作る。

### D. 日本語のタイポグラフィ

- [ ] **フォントは日本語を先頭に**（Hiragino Kaku Gothic ProN → Noto Sans JP →…）。
      `ui-sans-serif` を先頭に置くと欧文フォントが選ばれ、日本語だけフォールバックで
      描かれて字面が崩れる。`body_font` の先頭を見る。
- [ ] **行間は 1.7。** 情報密度を上げるつもりで 1.45 に詰めたら一気に読みにくくなった。
      欧文の詰め方をそのまま日本語に持ち込まない。
- [ ] 行の縦 padding は `py-2`〜`py-2.5`。`py-1` は窮屈（スマホで指摘された）。
- [ ] 数字は `font-variant-numeric: tabular-nums`。桁が揃わないと縦に比較できない。
- [ ] **`text-transform: uppercase` を使っていないか。日本語には何も起きない。**
      「小さく・大文字・字間広め」でラベルを立てるのは欧文の定石で、日本語では
      字間が広がるだけの「薄い本文」になる。見出しは**本文より強く**する
      （本文色 / 13px / 700）。CSS だけでなく Tailwind の `uppercase` も探すこと。

### E. 情報の編成（見た目より効く）

- [ ] ⚠️⚠️ **「見づらい」に線・枠・色を足す前に、並べ替えで解けないか試す。**
      出走表の「数字ばかりで誤認しそう」に区切り線を入れたら
      「**線があると逆に見づらい**」と却下された（2026-08-24）。本体は線の有無ではなく
      **数字の列が連続していること**で、列を並べ替えて文字の列（馬名・騎手）と
      バッジで挟むと解けた。**要素を足すのは最後の手段**（足すほど密度が上がる）。
- [ ] **値そのものに意味が無い列は、数字をやめる。**
      符号と大きさだけ要るもの→**中央から左右に伸びる棒**、
      少数のカウント→**該当項目の頭文字**（個数だけでなく中身も分かる）、
      順位→**単位を添える**（`3` ではなく `3位`。隣の順位列と取り違えない）。
      値は `aria-label` / `title` に残すので情報は減らない。
- [ ] ⚠️ **図に置き換えたら「一番よくある値」が本番で何px になるかを測る。**
      列幅を見出し任せにして、典型値の棒が**最大7px**で読めなかったことがある。
      数値と違い、図は幅が足りないと情報がゼロになる。目盛りの上限も
      **レース内の相対にしない**（値が小さい回でも棒が伸びて誇張される）。


- [ ] **結論が根拠より上にあるか。** 「情報量が多い」「スクロールが面倒」の正体は
      量ではなく**編成**だった。減らす前に並べ替えを試す。
- [ ] **すぐ下に同じ情報があるなら、要約バッジは置かない。**
      会場名の隣に `12R` を出していたが、その真下に 1R〜12R が並んでいるので
      数えるまでもなかった（2026-08-24 指摘「12Rというのいらない」）。
      見出しの邪魔をしていただけで、外したら中央寄せにもできた。
- [ ] **同じデータを2つの形で出していないか。** 出走表の列をソートすれば済むものを
      別パネルで再掲していないか（総合TOP6がそうだった）。
      ただし**名前が食い違うなら残す** —「妙味」がパネル（期待値）とEV列（人気順位−指数順位）で
      別物だった。名前が同じでも中身が違うなら別の情報。
- [ ] **同じ語で呼ぶ指標を複数の定数で数えていないか。** 「軸の数」を
      `FAV_AXES`(3) / `CLEAN_AXES`(4) / マトリクスの登場(5) で別々に数えていて、
      コメントと tooltip が実装から乖離していた。
- [ ] **測定値が低いことは、画面から消してよい理由にならない。**
      斤量比較を「ランダム比0.75x」だけを根拠に消して差し戻した。
      実測が言えるのは「単独で軸を選ぶと当たらない」までで、他の材料と併せて見る使い方は
      否定していない。**消す前に使っているか訊く。**
- [ ] **押せる物は押せると分かる形にする。** 素のテキストリンクを並べたら
      「リンクだと視認しにくい」と言われた（2026-08-24）。面・枠・矢印を付ける（`.link-card`）。
- [ ] **内部遷移は `next/link`。** 素の `<a>` はフルページリロードになり、
      「スクロールが面倒」を減らすはずの導線が体感で逆効果になる。
- [ ] **共通クラスに切り出したとき `:focus-visible` も一緒に移したか。**
      `:hover` は目に付くので移すが、`:focus-visible` は普段見えないので落ちる。
      落とすとキーボード操作時に現在位置が分からなくなる。
- [ ] **CSS変数の値を数値のままコピーしていないか。** 透明度違いが欲しいときに
      `rgba(245,158,11,.34)` と直書きすると、トークンを変えてもここだけ旧色で残る。
      `color-mix(in srgb, var(--token) N%, transparent)` か、派生色を別トークンにする。
- [ ] **状態と URL を二重に持っていないか。** 両方で持つと同期 effect が要り、
      クライアント遷移で URL だけ変わったとき追従せず、effect 内の setState が
      cascading render になる。**URL を唯一の持ち主にして `router.replace` で書く。**
- [ ] **`<Suspense>` の境界を広く取りすぎていないか。** ページ全体を包むと
      静的HTMLが空になり、見出しごと真っ白になる。境界の中は
      **URL のクエリに依存する部分だけ**にする。
- [ ] **条件付きで消えるパネルを別ページへ切り出すときは、リンクの出し分けもする。**
      `if (!available) return null` するコンポーネントは、親ページにある限り
      「出ないときは何も無い」で辻褄が合う。別ルートへ移すとリンクは無条件に描かれるので、
      **戻るリンクだけの空ページ**という行き止まりができる。移動先にも「まだ出せない理由」を描く。
- [ ] **切り出すとき、移動元にあったエラー処理を持っていったか。**
      「404 でも読み込み中のまま固まらない」修正を置き去りにして、
      **直したはずのバグを実質復活させた**ことがある。
- [ ] **折りたたまない。** `<details>` は使わない（所有者の明示指示。
      毎回見るものを畳むと毎回1タップ増える）。現状 `app/` に `<details>` は0件。

### F. 消すとき

- [ ] **配列を空にして畳まない。** `MENU_ITEMS = []` にしたら描画ブロック・開閉 state・
      アイコン import が到達不能コードとして残り、lint も型検査も通ってしまった。
      **構造ごと消す。** 復活させるならそのとき書き直す。
- [ ] 消したブロックの docstring / コメントが孤児として残っていないか。
      `//` だけ探して `/** */` を取り残した実績がある。

- [ ] ⚠️ **表示切り替え（`hidden` `sm:` 等）を、自前で display を持つコンポーネントに渡していないか。**
      `display` 系のユーティリティ同士は特異度が同じなので、**CSSの並び順で勝敗が決まる**。
      `inline-block` を内蔵したバッジに `className="hidden sm:inline-block"` を渡したら
      `hidden` が負けて、**実機でバッジが二重に出た**（2026-08-24 スマホ指摘）。
      切り替えは display を持たない**親**に載せる。
      ⚠️ **jsdom はメディアクエリを解釈しないのでテストで再現できない。**
      「二重に見える」ではなく「切り替えを親が持っていること」を固定する。
- [ ] ⚠️ **バッジを数えるテストは、包んでいる親も拾う。** 親の `textContent` は
      中身と同じになるので、`children.length === 0` で葉に絞る（実際に3個と誤検出した）。

### G. タップ・ARIA（Vercel 側の担当だが、実際に踏んだので置いておく）

- [ ] **タップ可能な要素に `touch-action: manipulation` があるか。**
      無いとダブルタップ拡大の待ち時間（約300ms）がそのまま反応の鈍さになる。
      リポジトリ全体で0件だった実績あり。
- [ ] **`<th>` に `role="button"` を付けていないか。** `columnheader` の暗黙ロールを
      上書きするので **`aria-sort` が無効な属性になる**（並べ替えの状態が読み上げられない）。
      `tabIndex` + `onKeyDown` だけで操作は成立する。
      **役割を足すつもりの ARIA が、元からある役割を消すことがある。**
