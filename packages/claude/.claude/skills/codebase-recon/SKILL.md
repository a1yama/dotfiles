# コードベース初期調査

アドホックに Bash を並べず、以下の順で調べる。Bash は `git log` / `git diff` などの VCS 操作に限る
(`grep` / `ls` / `find` / `cat` は PreToolUse フックで拒否される)。

## 手順

1. **構成の把握 — Glob**
   - `**/*.{ts,tsx}` `**/{Makefile,package.json,pyproject.toml,go.mod}` でエントリポイントと設定ファイルを列挙する
   - ディレクトリ一覧が欲しいだけなら Glob のパターンで代用し、`ls` を打たない

2. **シンボル・文字列の横断検索 — Grep**
   - 1クエリで全体を検索する。`| head` で削らず `output_mode` と `head_limit` を使う
   - `output_mode: "files_with_matches"` — どのファイルにあるか
   - `output_mode: "content"` + `-n` + `-C 2` — 前後の文脈込みで読む
   - `output_mode: "count"` — 分布・件数だけ知りたいとき
   - 定義箇所を探すときは `type` / `glob` で言語を絞る

3. **該当箇所だけ Read**
   - Grep が返した行番号を `offset` / `limit` に渡して範囲読みする。最初から全文を読まない
   - 200行を超えるファイルは、まず関数定義だけを Grep してから範囲を決める

4. **広範囲なら委譲**
   - 複数ディレクトリ・複数の命名規則にまたがる探索は Explore サブエージェントに渡し、結論だけ受け取る
   - 探索軸が定まらず、レイヤをまたいで追う必要がある大規模調査は `recon-fable`(Fable 5)に委譲する
   - ただしユーザーがサブエージェントの使用を禁じている場合は自分で 1〜3 を回す

5. **履歴の確認 — ここだけ Bash**
   - `git log --oneline -20 -- <path>` / `git diff` で、その箇所が最近なぜ変わったかを見る

## 報告

調べ終えたら次を1回にまとめて返す。ファイルの中身をそのまま貼らない。

- エントリポイントと主要モジュールの役割(`path:line` で参照)
- 問われた処理がどこにあるか、呼び出し元・呼び出し先
- 読んでいない範囲があるならそれを明示する
