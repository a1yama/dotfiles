# a1yama の文体プロファイル

## 何のためのファイルか

冗長さを削り、AI臭を削っても、まだ「この人が書いた文章」にはならない。最後に残るのが文体の再現で、これはルールではなく**実測された癖**でしか埋められない。このファイルはその実測値である。

対象は a1yama が書いた（書く）文章だけ。他の書き手の原稿には使わない。

## 出典と測り方

出典は https://a1yama.hatenablog.com/ の全143記事（2015-12-17 〜 2025-01-13）。**AIを使わずに書かれた文章**であることがこのコーパスの価値で、だから数値がそのまま「本人の癖」になる。

2026-09-14 に全記事を取得し、はてなの定型文・広告・アフィリエイト枠・コードブロックを除いた本文 73,669字を測定した。文の分割は `scripts/lint.py` の `body_sentences()` を使っているので、以下の数値は lint の出力とそのまま比較できる。全記事で 2,074文、うち800字以上の散文21記事で 788文。

コーパス自体はリポジトリに置いていない。再測定が必要なら上記URLの `/archive?page=N` から辿れる。第三者の実名が出てくる記事があるため、引用は本人の記述に限っている。

## 転写できるもの（業務文書にもそのまま効く）

以下は2023〜2025年の業務寄りの記事（Kyashアドベントカレンダー、入社エントリ、2025年のcommitment）でも維持されていた。社内ドキュメント・障害報告・PRのdescriptionに適用してよい。

**接続詞をほぼ使わない。** 全記事で「さらに」1回、「そのため」2回、「つまり」0回、「このように」0回。段落を接続詞で始めない。論理はつながっているので接続詞を足さなくても読める、という書き方をしている。

**理由は「ので」、逆接は「けど」。** 「ので、」183回に対し「から、」8回。「けど」164回に対し「しかし」10回、「一方で」0回。硬い接続語に置き換えない。

**「〜と思います」で着地する。** 全文の11.4%（業務寄り3記事だけでも10.7%）。lint はヘッジとして疑う位置にあるが、これは a1yama のヘッジではなく**着地の型**である。削ると別人になる。ただし事実を述べる文に付いていたら、それは本来のヘッジなので削ってよい。

**1文1行で改行する。** 句点を打たずに改行だけで区切る行の割合は、2016〜2019年で30〜40%、2024年以降は94〜95%。近年の書き方はほぼ「1行1文・句点なし」。原文がこの形なら、句点を補って整えない。

この書き方は近年だけのものではない。400字以上の67記事を測ると、句点をほとんど打たない記事は9本あり、2015年・2017年・2018年・2019年・2020年にも散っている（2024年・2025年の2本だけではない）。年ごとの行数比では平均に埋もれて見えないだけで、記事単位では昔から出てくる形である。

判定は行末だけでは足りない。ハードラップされた普通の文書も行末に句点が来ないからで、分かれるのは文書全体の句点の量になる。地の文100字あたりの句点数を測ると、その9本が 0.00〜0.36、残りの58本が 0.65〜4.70 で、0.36と0.65の間に谷がある。9本はいずれも句点なし行の割合が0.92以上で、2つの指標が完全に一致している。`lint.py` はこの両方を見て `unpunctuated_lines` を出す（閾値は谷の中の0.5）。

**括弧で自己注釈を挟む。** 文の5.0%。「（そんなこと気にするユーザは少ないだろうけど）」「（これで開発効率ががくっとさがったので）」のように、本文の主張を自分で相対化する。削ると平板になる。

**分からないことを分からないと書く。** 「詳しい人教えてください」「間違っていたら教えてください」「この辺の仕様が全くわからない…」。ヘッジではなく事実の表明なので、断定に直さない。

**一人称は場面で変わる。** 2016〜2020年のブログは「僕」53回。2023年以降の業務寄りの記事では「僕」0回で、「私」か「自分」か、そもそも主語なし。業務文書で「僕」に直すのは誤り。

## 転写できないもの（ブログ限定）

以下はブログの語り口であって、障害報告や全社アナウンスに移すと事故になる。**原文がブログ・雑記・個人の振り返りのときだけ使う。**

- 感嘆の連打（「最高！！！」「便利！」「the 簡単!!」）
- 自己ツッコミの独立行（「ならやるな」「察しの通りやる気が殆ど無いです」「これもなｒ」）
- 読者への呼びかけと自問自答（「ありますよね？」→「僕はありました。今日ありました。」）
- 「めんどくさい」15回、「知らんけど」、「ｗ」
- 言い切りの一語見出し（「次！」「おわり！」「完全なメモ」「THE☆雑」）

判断に迷ったら移さない。ブログ側の癖は、業務文書では「ふざけている」と読まれる。

## 敬体と常体は揃えなくてよい

散文記事の文末は敬体410・常体139。敬体が主だが、**21記事中9記事（45%）で両者が混在している。**

> 先日はじめてパーマをしてきた。知人が美容師のアシスタントをしていて、カラーやパーマの練習をしている。（中略）流石にカラー剤などのお金は支払わないといけないらしく、1回2000円です。

常体で語りながら、読者に向けた説明の文だけ敬体に戻る。これが a1yama の地の文である。

ただし SKILL.md の「文体と丁寧さを勝手に変えない」が優先する。**原文が敬体で統一されているものを、この節を根拠に常体へ崩さない。** ここで言っているのは、原文にもともとある揺れを「統一されていないから」と直しに行くな、ということだけ。

## lint.py の判定を読み替える

`scripts/lint.py` の閾値は一般的な業務文書向けなので、a1yama の文章には合わない箇所がある。実際に本人の記事を `--prose` で通すとこうなる。

| 記事 | `--prose` の burstiness | 警告数（voice なし → あり） |
|---|---|---|
| 2024年 入社1年 | -0.419 | 2 → 1 |
| 2023年 Kyashアドベント | -0.365 | 6 → 1 |
| 2018年 退職エントリー | -0.358 | 4 → 0 |
| 2025年 commitment | -0.235 | 4 → 2 |

記事ごとの burstiness の中央値は -0.306 で、lint の `--prose` 閾値 -0.24 を恒常的に下回る。**a1yama らしく書くと burstiness 警告が出る。** 原文が a1yama のものなら、この警告を根拠に文を刻まない。

`--voice a1yama` を付けたあとに残るのは体言止めの不在・句点なし行・絵文字で、いずれも「情報」であって直せという指示ではない。

同様に、lint の置換候補リストのうち以下は本人の常用語なので残す。**lint は完全一致で数えるので、語形をそのまま並べている。**

| 語 | 全記事での出現 | lint の分類 |
|---|---|---|
| ちゃんと | 26 | empty_modifier |
| かなり | 22 | empty_modifier |
| していく | 12 | translationese |
| 単に | 12 | ai_syntax |
| 様々な | 10 | empty_modifier |
| 基本的に | 8 | empty_modifier |
| を行う | 7 | nominal_predicate |
| しっかりと | 3 | empty_modifier |
| を行い | 2 | nominal_predicate |

「していきたい」13回、「していこう」8回も同じ癖だが、lint はこの語形を見ていないので表には入れていない。逆に「を進めていく」は語尾が「していく」と同じでも**実測0回**なので残さない。判断の根拠は語形の整合ではなく、本人が実際に使っているかどうかにある。

逆に、以下は10年143記事で**一度も使っていない**。原稿に出てきたらAIが足したものなので、迷わず削ってよい。

することが可能 / における / を通じて / これにより / という形で / を実施 / つまり / このように / と考えられます / と思われます / 重要なのは

`python3 scripts/lint.py <ファイル> --voice a1yama` で、この読み替えを反映した判定になる。

## 添削後のチェック

添削結果が a1yama の文章として出せる状態か、最後にこれだけ見る。

- 太字を足していないか（本人は0件）
- 段落の頭に「また」「さらに」「そのため」を足していないか
- 「〜ので」を「〜ため」に、「〜けど」を「しかし」に直していないか
- 「〜と思います」を全部断定に直していないか
- 原文が1行1文・句点なしなら、その形を残したか
- 一人称を場面に合わない側へ変えていないか（業務文書で「僕」、ブログで「私」）
- 括弧の自己注釈を削っていないか
